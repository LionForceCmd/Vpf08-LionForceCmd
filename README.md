# movie-mcp — кино-каталог на MCP + Telegram-бот

Домашнее задание по модулю «MCP (Model Context Protocol)».
Базовый проект `product-mcp` из урока перенесён в предметную область **кино и сериалы**
и доработан: 19 MCP-инструментов вместо 4, 151 запись в базе вместо 100 товаров,
ресурсы MCP, настоящий JSON-RPC 2.0 / Streamable HTTP и 178 автотестов.

## Короткое описание

Проект состоит из двух независимых частей, связанных протоколом MCP.
`mcp_server` — это FastAPI-сервер, который отдаёт каталог фильмов из SQLite3
в виде MCP-инструментов: поиск по названию и жанру, карточка фильма, фильмография
актёров и режиссёров, топы по рейтингу и кассам, статистика коллекции, подбор
похожих фильмов, личные оценки и избранное, расчёт окупаемости кассовых сборов и
безопасный калькулятор. Каждая функция описана в MCP JSON Schema
(`name` / `description` / `inputSchema`), поэтому модель сама выбирает нужный
инструмент, не зная ничего о структуре базы.

`telegram_bot` — это aiogram-бот, который по обычному человеческому запросу
получает у MCP-сервера список инструментов, передаёт его в LLM вместе с текстом
и историей диалога, выполняет выбранные моделью вызовы и возвращает готовый ответ.
Ключевая идея урока сохранена и усилена: инструменты вынесены в отдельный сервис,
поэтому к одному и тому же набору функций можно подключить сколько угодно агентов.

## Быстрый старт

### 1. Установить зависимости

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate

pip install -r mcp_server/requirements.txt -r telegram_bot/requirements.txt
```

Для разработки и тестов добавьте `requirements-dev.txt`:

```bash
pip install -r requirements-dev.txt
```

### 2. Настроить ключи

```bash
copy .env.example .env      # Windows
cp .env.example .env        # macOS / Linux
```

Заполните в `.env`:

```ini
TELEGRAM_BOT_TOKEN=123456:AA...      # токен от @BotFather
OPENAI_API_KEY=sk-...                # ключ OpenAI
LLM_MODEL=gpt-4o-mini                # или gpt-4o, deepseek-chat, qwen-plus
```

Подойдёт любой OpenAI-совместимый провайдер — достаточно указать
`OPENAI_BASE_URL` (например `https://api.deepseek.com/v1`).

### 3. Запустить MCP-сервер

```bash
cd mcp_server
python server.py
```

При первом запуске автоматически создаётся `mcp_server/movies.db` и заполняется
151 фильмом. Проверить, что всё живо:

```bash
curl http://127.0.0.1:8000/health
# {"status":"ok","server":"movie-mcp","movies_in_db":151,"tools_count":19,...}
```

Интерактивная документация: <http://127.0.0.1:8000/docs>

### 4. Запустить бота

В **другом** терминале:

```bash
cd telegram_bot
python bot.py
```

Откройте бота в Telegram и напишите `/start`.

## Архитектура

```
   Telegram                      MCP (JSON-RPC 2.0 / Streamable HTTP)
      │                                      │
      ▼                                      ▼
┌───────────┐   текст + инструменты   ┌──────────────┐    tools/call    ┌──────────┐
│    LLM    │ ──────────────────────► │  mcp_client  │ ──────────────► │  FastAPI │
│ (OpenAI)  │ ◄────────────────────── │ telegram_bot │ ◄────────────── │  + MCP   │
└───────────┘   текст + tool_calls   └──────────────┘    JSON-ответ   └────┬─────┘
                                                                          │
                                                            ┌─────────────┴─────────────┐
                                                            ▼                           ▼
                                                     ┌─────────────┐            ┌──────────┐
                                                     │  tools.py   │            │ SQLite3  │
                                                     │ 19 схем    │───────────►│ movies,  │
                                                     │ обработчики │            │ people,  │
                                                     └─────────────┘            │ credits, │
                                                                            └──────────┘
                                                                              user_ratings,
                                                                              favorites
```

Методы MCP, которые поддерживает сервер:

| Метод | Назначение |
|---|---|
| `initialize` | Рукопожатие, согласование версии протокола |
| `tools/list` | 19 инструментов в MCP JSON Schema |
| `tools/call` | Вызов инструмента, ответ в `content` + `structuredContent` |
| `resources/list`, `resources/read` | Статистика, список жанров и топ каталога |
| `ping` | Проверка живости соединения |

Поддерживаемые версии протокола: `2024-11-05`, `2025-03-26`, `2025-06-18`,
`2025-11-25`, `2026-07-28`.

## Список MCP-инструментов

**Чтение каталога**
- `list_movies` — список с фильтрами (тип, жанр, годы, рейтинг, бюджет) и сортировкой
- `find_movie` — поиск по названию, в том числе по оригинальному
- `get_movie` — полная карточка по id: описание, актёры, отметки пользователя
- `find_movies_by_genre` — подборка по жанру
- `get_top_movies` — топ по рейтингу, сборам, бюджету, голосам или году
- `get_movie_stats` — статистика: типы, жанры, десятилетия, средний рейтинг, суммарные сборы
- `get_similar_movies` — похожие по жанрам, режиссёру, типу и году
- `get_person_filmography` — фильмография актёра или режиссёра
- `find_person` — поиск персоны по имени

**Изменение каталога**
- `add_movie`, `update_movie`, `delete_movie`

**Персональные данные**
- `rate_movie`, `get_user_ratings` — оценки от 1 до 10
- `toggle_favorite`, `get_favorites` — избранное
- `get_recommendations` — подбор по жанрам высоких оценок

**Вычисления**
- `box_office_stats` — прибыль, ROI, окупаемость по бюджету и сборам
- `calculate` — безопасный калькулятор (без `eval`, разбор через `ast`)

## Безопасность калькулятора

Урок справедливо предупреждает: `eval()` позволяет выполнить произвольный код на
сервере. Поэтому выражения разбираются деревом `ast` и считаются вручную:

- разрешены только арифметические операции, скобки и белый список функций
  (`sqrt`, `abs`, `round`, `min`, `max`, `log`, `floor`, `ceil`, …);
- любое обращение к атрибутам (`__class__`, `__subclasses__`), `import`,
  `lambda`, comprehensions и Comparisons отклоняются;
- ограничены показатель степени, длина выражения и итоговое значение.

Попытки `__import__('os').system(...)` и `open(...).read()` возвращают ошибку,
а не выполняются. Это проверяется тестами и в `scripts/smoke_test.py`.

## Тестирование

```bash
pytest                       # 178 тестов
python scripts/smoke_test.py # сквозная проверка без Telegram
```

Что покрыто:

- `test_calculators.py` — безопасность и точность калькулятора, форматирование;
- `test_db.py` — схема, поиск с учётом регистра кириллицы, фильтры, CRUD,
  разделение данных по пользователям, аналитика;
- `test_mcp_protocol.py` — рукопожатие, `tools/list`, `tools/call`, ресурсы,
  коды ошибок JSON-RPC, batch-запросы;
- `test_bot_agent.py` — MCP-клиент, конвертация схем в формат OpenAI, цикл
  агента (выбор инструмента, несколько раундов, обработка ошибок, резервный
  JSON-план), разбивка длинных сообщений Telegram;
- `test_spec_compliance.py` — сервер поднимается на реальном порту, и к нему
  подключается **официальный SDK `mcp`**: `initialize`, `tools/list`,
  `tools/call`, `resources/*`. Это подтверждает, что сервер соответствует
  спецификации MCP, а не просто имитирует её.

Тесты не требуют ни Telegram, ни ключей OpenAI: LLM подменяется скриптом,
а MCP-клиент работает с ASGI-приложением сервера.

Живой прогон с настоящей моделью (нужен `OPENAI_API_KEY` в `.env`):

```bash
python scripts/smoke_test.py --live
```

## Дополнительные настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MCP_SERVER_URL` | `http://127.0.0.1:8000/mcp` | Адрес MCP-сервера для бота |
| `MCP_PORT` / `MCP_HOST` | `8000` / `127.0.0.1` | Адрес MCP-сервера |
| `MCP_API_TOKEN` | — | Если задан, сервер требует `Authorization: Bearer <token>` |
| `MOVIE_DB_PATH` | `mcp_server/movies.db` | Путь к базе |
| `LLM_MODEL` | `gpt-4o-mini` | Модель OpenAI или совместимая |
| `OPENAI_BASE_URL` | — | Endpoint другого провайдера |
| `MAX_TOOL_ROUNDS` | `6` | Сколько раз агент может вызвать инструменты подряд |
| `HISTORY_TURNS` | `12` | Сколько сообщений диалога уходит в модель |

## Возможные развития

- подключить внешние API (TMDB/OMDb) как дополнительные MCP-инструменты;
- перенести состояние диалога из памяти в Redis, чтобы бот переживал перезапуск;
- добавить Streamable HTTP SSE-уведомления вместо опроса;
- подключить второй агент (например, CLI или Discord) к тому же серверу —
  инструменты остаются переиспользуемыми, это и есть смысл MCP.
